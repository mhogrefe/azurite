# Azurite

A Lean 4 library for efficient, formally verified mathematical computation.

Azurite provides array-backed data structures for polynomials, vectors, and matrices with proven equivalences to their Mathlib counterparts. Every computable operation has a corresponding proof that it agrees with the abstract Mathlib definition.

## Module Map

### Core Data Structures

| Module | Description |
|--------|-------------|
| `AzNat/` | Computable multi-limb natural numbers over `Array UInt64`. Three-way multiplication (schoolbook / Karatsuba / Toom-Cook 3, with configurable basecase thresholds) and matching three-way `square`. Division: schoolbook `divMod` (Möller–Granlund reciprocal steps from `UInt64/`, with single- and double-limb divisor fast paths) plus a recursive divide-and-conquer variant (`Div/Recursive`); integer square root with remainder (`sqrtRem`); proven perfect-square test (`isSquare`, mod-256 quadratic-residue filter on the low byte + `square (sqrt n) == n` fallback). Exponentiation `pow` (sliding-window) and `powBinary` (binary, for benchmarking), both using the fast `square`. Binary GCD (Stein's algorithm, `gcd`) with bulk trailing-zeros shifts. Rounded division and right shift (`divRound`, `shiftRightRound`) correct against the `Rounding/` spec. Bit-level toolkit (`testBit`/`setBit`/`clearBit`/`getBits`, `modPow2`, `lowMask`, `size`, `trailingZeros`, `isMultipleOfPow2`). Base-`b` string conversion and parsing (`toStringBase`/`parseBase`) via base-10¹⁹ limb digits (`DivMod10p19`, `LimbDigits`). Also provides a `ParsableElement` instance for use as an `AzVector` / `AzMatrix` coefficient type. The verified `CommSemiring` instance routes all its data through the fast operations: `npow` is the sliding-window power, `natCast` is the limb-level `AzNat.ofNat` (not the default unary cast), and `n • a` is one cast plus one multiplication (not `n` additions). |
| `AzInt/` | Computable integers as a sign-magnitude pair `(sign : Bool, abs : AzNat)` with a canonical zero invariant (`abs = 0 → sign = true`). Includes conversions to/from all Lean fixed-width int/uint types and `AzNat`, comparison against `UInt64`/`Int64`/`AzNat`, a custom `compare` with derived `Ord`/`LE`/`LT`/`Max`/`Min`, full ring arithmetic (add/sub/mul over `AzNat` magnitudes), Euclidean division `edivMod`, shifts (`shiftLeft`/`shiftRight`) and rounded division/right-shift (`divRound`/`shiftRightRound`, correct against the `Rounding/` spec), parity tests, `pow2`, `lowMask`, `isPowerOfTwo`, exponentiation `pow` (sign rule over `AzNat`'s sliding-window power, also the `CommRing`'s `npow`), bit-size, trailing-zeros, parsing, `toString`, and a `ParsableElement` instance (so `AzInt` works as a coefficient type for `AzVector` / `AzMatrix` `parseStr`). The verified `CommRing` instance routes all its data through the fast operations: `NatCast`/`IntCast` are the limb-level `AzNat.ofNat`/`ofInt` (with `toInt_natCast`/`toInt_intCast`, not the default unary casts), and `n • z` / `i • z` are one cast plus one multiplication (not `n` additions). |
| `AzRat/` | Computable rationals in lowest terms: a `(sign : Bool, num : AzNat, den : AzNat)` with proofs `den ≠ 0`, `num = 0 → sign = true` (canonical zero), and `AzNat.coprime num den` (reduced). Computable conversions `toRat`/`ofRat` to/from `ℚ` (`toRat` builds the `ℚ` directly via `Rat.mk'`, the AzRat invariants being exactly `Rat.mk'`'s nonzero-denominator and coprimality requirements via `AzNat.coprime_iff`) with round-trip equivalence both ways (`toRat_ofRat`, `ofRat_toRat`, axiom-clean). Conversions `AzNat.toAzRat` (`n` as `n/1`), `AzInt.toAzRat` (`z` as `|z|/1` with `z`'s sign), and every primitive `UIntN`/`IntN`/`USize`/`ISize` (`.toAzRat`, delegating through `.toAzInt`) with correctness (`toRat_toAzRat`, `toRat_toAzRat_int`, and per-primitive `*.toRat_toAzRat` agreeing with `toNat`/`toInt` casts into `ℚ`). Pair constructors `ofAzNats`/`ofAzInts` (via the shared sign-aware core `ofSignAzNats`): reduce by a single `AzNat.gcd`, canonicalize zero, and map a zero denominator to `0` (the `mkRat` convention); correctness `toRat_ofAzNats`/`toRat_ofAzInts` (`= n / d` as field division in `ℚ`, no nonzero hypotheses needed). Canonical zero `0 : AzRat` and one `1 : AzRat` (`OfNat`/`Zero`/`One`/`Inhabited` instances mirroring `AzNat`/`AzInt`, with `toRat_zero`/`toRat_one`/`default_eq_zero` and the `ofRat_zero`/`ofRat_one` converses). String rendering `toChars`/`toString` (`"0"`, `"4"`, `"1/3"`, `"-1/3"`: sign on the numerator, no `"/den"` suffix for integers) and permissive parsing `parse` (unreduced fractions reduce, `"5/0" ↦ 0` per the `mkRat` convention; negative denominators and `"-0"` rejected), with the round-trip `parse_toString : parse (toString q) = some q`. Unary operations `neg` (the `Neg` instance), `abs`, and `inv` (the `Inv` instance, `0⁻¹ = 0`) — all sign/field-level with no limb arithmetic (`inv` swaps `num`/`den`, which preserves coprimality) — with correctness in both directions (`toRat_neg`/`toRat_abs`/`toRat_inv` and `ofRat_neg`/`ofRat_abs`/`ofRat_inv`). Multiplication (`Mul` instance) with **cross-gcd reduction**: exactly two `AzNat.gcd` calls on the cross pairs `(num x, den y)`/`(den x, num y)`, after which the product of the reduced parts is already in lowest terms (`coprime_cross_mul`) — no gcd of the products is ever computed; correctness `toRat_mul`/`ofRat_mul`. Division (`Div` instance, `x / 0 = 0`) duplicates the multiplication algorithm with the divisor's `num`/`den` roles swapped — no intermediate `y⁻¹` is allocated, yet `div_eq_mul_inv : x / y = x * y⁻¹` holds *structurally*; correctness `toRat_div`/`ofRat_div`. Shifts `<<<`/`>>>` (`HShiftLeft`/`HShiftRight` instances) scale by `2^n` with **no gcd at all**: the shift splits at `k = min n v₂(·)` (read off by `AzNat.trailingZeros`) into an exact limb shift on one component and a pure shift on the other (`coprime_shift`); correctness `toRat_shiftLeft`/`toRat_shiftRight` + `ofRat` converses. Addition (`Add` instance) with **cross-denominator gcd splitting**: `g = gcd(b,d)`; if `g = 1` the sum `(ad+bc)/(bd)` needs no reduction at all; otherwise the small numerator `t = a·d' + b'·c` over `g·b'·d'` is automatically coprime to `b'` and `d'`, so only `g₂ = gcd(t, g)` (small arguments) remains to divide out — signs via `combineSigned` (magnitude compare, cancellation to canonical zero); correctness `toRat_add`/`ofRat_add`. Subtraction (`Sub` instance) duplicates the addition algorithm with the subtrahend's sign flipped inline — no intermediate `-y` is allocated, yet `sub_eq_add_neg : x - y = x + (-y)` holds *structurally*; correctness `toRat_sub`/`ofRat_sub`. Exponentiation `pow`/`zpow` with **no reduction at all**: numerator and denominator are powered separately by `AzNat`'s sliding-window power (coprimes stay coprime under powers), the sign rule is `AzInt.pow`'s, and a negative exponent runs the same powers with the num/den roles swapped (the reciprocal of a reduced fraction is the swap, `0^-k = 0`) — installed as the `Field`'s `npow`/`zpow`, so `q ^ (n : ℕ)` and `q ^ (z : ℤ)` are `O(log n)` multiplications and `q.pow n = q ^ n` definitionally; correctness `toRat_pow`/`toRat_zpow` + `ofRat` converses. Rounding `AzRat.round q mode : AzInt × Ordering` (signed numerator over denominator via `AzInt.divRound`, accepting a `RoundingMode`; the `Ordering` records how the result compares to `toRat q`) with correctness `toInt_round` (value agrees with abstract `RoundingTarget.round intSet mode (toRat q)`) and `snd_round` (ordering tag = `compare` of rounded value vs `toRat q`). Base-2 logarithm `floorLogBase2Abs`/`ceilingLogBase2Abs : AzRat → ℤ` (limb-level via `AzNat.size` + `AzNat.normalizedCompare`, no GMP-backed `Nat.log2`) with correctness `floorLogBase2Abs_eq`/`ceilingLogBase2Abs_eq` (`= ⌊/⌈logb 2 |toRat q|⌋/⌉`, axiom-clean). Fast comparison `AzRat.cmp x y : Ordering` (staged, limb-level: sign → `|·|` vs 1 → num/den magnitudes → `floorLogBase2Abs` → cross-multiply, via `AzNat.compare`/`AzNat` mul) with correctness `cmp_eq_compare : cmp x y = compare (toRat x) (toRat y)`, backing the derived `Ord`/`LE`/`LT`/`Max`/`Min` instances and the verified `LinearOrder AzRat` (with `compare = cmp`, so deciding an inequality never computes in `ℚ`). Algebraic instances (`Instances.lean`): computable casts `NatCast`/`IntCast` (limb-level via `AzNat.ofNat`/`AzInt.ofInt` + `toAzRat`) and `RatCast`/`NNRatCast` (= `ofRat`) with `toRat_natCast`/`toRat_intCast`/`toRat_ratCast`, plus verified `Field` and `IsStrictOrderedRing` instances (every law transported from `ℚ` through `toRat`; all data fields are the existing verified operations — including `npow`/`zpow` = `pow`/`zpow` and `n • q` / `z • q` / `q • r` as one cast plus one multiplication — so no diamonds and no `O(n)` recursor defaults) — together with the `LinearOrder` this is the complete linearly-ordered-field API, and Mathlib's lattice `\|·\|` agrees with the constant-time `AzRat.abs` (`abs_eq`, oriented so `simp` normalizes to the `\|·\|` notation; `toRat_abs'`/`ofRat_abs'` restate the commutation facts in that normal form). `ParsableElement` and `ParsableCoeff` instances (both routing through the limb-level `toChars`/`parse`, with the proven char-set facts `mem_toChars_digit_or_dash_or_slash` etc.), so `AzRat` works as an entry type for `AzVector`/`AzMatrix` and as a coefficient type for `AzPolynomial`/`AzMvPolynomial` string conversion — e.g. `"[1/2, -1/3; 0, 2]"` parses as an `AzMatrix AzRat 2 2` and `"3/2*x^2-1/3*x+5"` as an `AzPolynomial AzRat`, both round-tripping. |
| `ExhaustiveGenerator/` | The `Azurite.ExhaustiveGenerator T` typeclass (a Lean port of Malachite's `exhaustive_*` iterators): a generator `gen : ℕ → Option T` bundled with the headline field `occurs_exactly_once : ∀ t, ∃! n, gen n = some t` — every value occurs at exactly one position. The `Option` codomain lets a generator be **infinite** (always `some`) or **finite** (eventually `none`, e.g. `UInt8` stops after `2^8` values). Two `@[reducible]` builders factor the proofs: `ExhaustiveGenerator.ofBijective (f : ℕ → T) (hf : Function.Bijective f)` (infinite, `gen n = some (f n)`, reuses existing bijectivity proofs) and `ExhaustiveGenerator.ofBoundedBij (card) (f) (hinj) (hsurj)` (finite, `gen n = if n < card then some (f n) else none`). The `ExhaustiveGenerator.firstN T n` helper (`(List.range n).filterMap gen`) previews the first `n` values, recovering the whole finite enumeration when `card ≤ n`. Instances (each named `<name>Gen`): `naturalsGen : ExhaustiveGenerator AzNat` (`0,1,2,…`, `f = AzNat.ofNat`, `naturals_bijective` from the `AzNat.toNat_ofNat`/`ofNat_toNat` round-trips). `PositiveNaturals` — `positiveNaturalsGen : ExhaustiveGenerator {n : AzNat // 0 < n}` (`1,2,3,…`, `ofNat_succ_pos` via the `AzNat.lt_iff_toNat_lt` bridge, surjectivity via `Nat.sub_add_cancel`). `Integers` — three half-line generators `positiveIntegersGen`/`nonnegativeIntegersGen`/`negativeIntegersGen` (subtypes `{z // 0 < z}`/`{z // 0 ≤ z}`/`{z // z < 0}`) plus the two zig-zag generators `integersGen : ExhaustiveGenerator AzInt` (`0,1,-1,2,-2,…`, the full type incl. `0`) and `nonzeroIntegersGen : ExhaustiveGenerator {z // z ≠ 0}` (`1,-1,2,-2,…`) — all on `AzInt.ofInt` with bijectivity from the `AzInt.toInt_ofInt`/`ofInt_toInt` round-trips and `AzInt.lt_iff_toInt_lt`/`le_iff_toInt_le` bridges (`split_ifs <;> omega` on parity for the zig-zags, `by_cases`/`omega` over `Int.toNat` for the surjective witnesses). `Unsigneds` — the FINITE generators `uint8Gen`/`uint16Gen`/`uint32Gen`/`uint64Gen` (Malachite `exhaustive_unsigneds`), each `ofBoundedBij (2^width) UIntXX.ofNat` with `hinj` from `UIntXX.toNat_ofNat'` and `hsurj` witness `t.toNat` via `UIntXX.toNat_lt`/`UIntXX.ofNat_toNat`; e.g. `firstN UInt8 300` has length `256` (stops at cardinality, demonstrating the finite path). The dependent `ExhaustiveGenerator.ofBoundedBijOn` builder (value `f n h` may use the in-range proof `h : n < card`) powers the FINITE monotone half-line generators over the fixed-width integers: `Signeds` (Malachite `exhaustive_natural_signeds`/`negative_signeds`/`positive_signeds`) has `nonnegative`/`negative`/`positive` × `Int8/16/32/64` (12 instances: `nonnegativeInt8Gen`…`positiveInt64Gen`, subtypes `{x // 0 ≤ x}`/`{x // x < 0}`/`{x // 0 < x}`, cards `2^(w-1)`/`2^(w-1)`/`2^(w-1)-1`), and `Unsigneds` adds `positiveUInt8Gen`…`positiveUInt64Gen` (`{x // 0 < x}`, card `2^w-1`). Three generic `positiveSignedGen`/`nonnegativeSignedGen`/`negativeSignedGen` builders (plus `positiveUnsignedGen`) do each proof once over an abstract `T` given its `toInt`/`ofInt` (or `toNat`/`ofNat`), an in-range round-trip `canon` (per width: `IntX.toInt_ofInt`'s `bmod` reduced by `Int.bmod_eq_of_le`; `UIntX.toNat_ofNat'`'s `%` by `Nat.mod_eq_of_lt`), range bounds `IntX.toInt_lt`/`le_toInt` (`UIntX.toNat_lt`), and the order↔`toInt`/`toNat` bridge `IntX.lt_iff_toInt_lt`/`le_iff_toInt_le` (`UIntX.lt_iff_toNat_lt`); each width is a one-line application. `Signeds` also has the two ZIG-ZAG signed generators (Malachite `exhaustive_signeds`/`nonzero_signeds`): `int8Gen`…`int64Gen : ExhaustiveGenerator IntX` (`0,1,-1,2,-2,…,MAX,-MAX,MIN`, full type) and `nonzeroInt8Gen`…`nonzeroInt64Gen : ExhaustiveGenerator {x // x ≠ 0}` (`1,-1,2,-2,…,MAX,-MAX,MIN`), built by the generic `zigZagSignedGen`/`zigZagNonzeroSignedGen`. These handle the ASYMMETRIC signed range `[-2^(w-1), 2^(w-1)-1]` (one extra negative): the symmetric zig-zag covers `[-MAX, MAX]` and `MIN = IntX.minValue` lands alone at the final index (via `IntX.toInt_minValue = -2^(w-1)`); injectivity/surjectivity reduce to `ℤ` through a `key` bridge (`toInt` of the finite value = the intended `ℤ`) then `split_ifs <;> omega`, the `MIN`-branch disjoint from the zig-zag branch since `MIN < -MAX`. `Count` proves how many elements each generator produces (from `occurs_exactly_once`, the count is `|T|`): the 7 infinite generators get `<name>Gen_infinite : Infinite T` (via `Infinite.of_injective` + the existing `_bijective` lemmas), and the 28 finite ones get `<name>Gen_card : Fintype.card T = N` (`N = 2^w`, `2^w-1`, `2^(w-1)`, or `2^(w-1)-1`). The ambient `Fintype` instances are Mathlib's own computable ones (`FinEnum`-derived for `UIntX`/`IntX`, `Subtype.fintype` for the order subtypes); each `<gen>_card` is a one-line application of the bridge `fintypeCard_eq_finiteCard` to the generator's `FiniteGenerator` data (below), on top of the framework lemmas `ExhaustiveGenerator.equivFin` (the finite `gen` shape yields `T ≃ Fin N`) and `fintypeCard_eq` (instance-independent card read-off, no `decide`). `Basic` also defines the two composition mixins: proof-only `Contiguous` (the `some`s form an initial segment) and `FiniteGenerator` (the finite BOUND as literal DATA `card` plus `gen_none`/`gen_some` bound proofs — the runtime radix for compositional generators, since even a computable `Fintype.card UInt64` would materialize a `2^64`-element `univ`; implies `Contiguous` via `FiniteGenerator.toContiguous`), with shape-keyed builders `FiniteGenerator.ofBoundedBij`/`ofBoundedBijOn`/`ofListNodup`/`map` giving every finite base generator a one-line instance carrying its literal bound (`2^w`, `2^w-1`, `2^(w-1)`, `2^(w-1)-1`, list length). `ZMods` supplies the modular-integer generators — `azZModGen : ExhaustiveGenerator (AzZMod m)` (residues `0..m-1`, card `m.toNat`) and `azZModPow2Gen : ExhaustiveGenerator (AzZModPow2 k)` (card `2^k`), each with `FiniteGenerator` data — the Azurite-native `exhaustive_unsigneds` analogue for the computable coefficient rings (no Malachite counterpart exists). Both types carry their canonicity proof (`⟨val, isLt⟩`), so `ofBoundedBijOn` constructs each residue DIRECTLY with no modular reduction; bijectivity = the `AzNat.toNat/ofNat` round-trips. Guards: base tables + caps, `AzZMod 3 × AzNat` (capped fair pair), `AzZMod 3 × AzZModPow2 1` (finite × finite), and **the chapter's motivating shape: `List (AzZMod 3)` — fair streams of polynomial coefficient lists over `ZMod p`, resolving through the finite rail of `exhaustive_vecs`** (same table as `List Ordering` under the card-3 relabeling — the fair machinery depends only on the cards). `Enums` ports four tiny explicit enumerations (Malachite `exhaustive_bools`/`orderings_increasing`/`exhaustive_orderings`/`exhaustive_rounding_modes`) via the `ExhaustiveGenerator.ofListNodup` builder (`gen n = l[n]?`, existence from completeness, uniqueness from `List.getElem?_inj` on a `Nodup` list): `boolsGen : ExhaustiveGenerator Bool` (`[false, true]`), `orderingsIncreasingGen`/`orderingsGen : ExhaustiveGenerator Ordering` (`[.lt,.eq,.gt]` and Equal-first `[.eq,.lt,.gt]`; the latter a named non-instance `def`), and `roundingModesGen : ExhaustiveGenerator RoundingMode` (Azurite's five-variant `RoundingMode` — no Malachite `Exact` — as `[.Down,.Up,.Floor,.Ceiling,.Nearest]`); `Nodup`/completeness by `decide` (`cases`+`decide` for `RoundingMode`). Counts `boolsGen_card = 2`, `orderingsIncreasingGen_card`/`orderingsGen_card = 3`, `roundingModesGen_card = 5` via `fintypeCard_eq_finiteCard` (`Fintype Bool`/`Ordering` exist in Mathlib; `Fintype RoundingMode` is a computable hand-written instance here). `Ranges` ports the two parametrized increasing range constructors (Malachite `primitive_int_increasing_range`/`primitive_int_increasing_inclusive_range`): given runtime bounds `(a b)`, `<type>RangeGen a b : ExhaustiveGenerator {x // a ≤ x ∧ x < b}` and `<type>RangeInclusiveGen a b : ExhaustiveGenerator {x // a ≤ x ∧ x ≤ b}` ascend `a, a+1, …` over all 8 fixed-width types (`int8RangeGen`…`uint64RangeInclusiveGen`, 16 wrappers). Four generic builders (`increasingRange{Signed,Unsigned}Gen`, `…Inclusive…`) via `ofBoundedBijOn` with the value carrying its membership proof; the EMPTY range (`a ≥ b`) needs no special case — card `0`, `gen ≡ none`, surjectivity vacuous. Each has a derived parametrized `Fintype` instance and a count `<type>RangeGen_card a b : Fintype.card … = (b−a)` (`.toNat` of `b.toInt − a.toInt`, `+1` inclusive; unsigned via `b.toNat − a.toNat`, inclusive `b.toNat + 1 − a.toNat` — the `+1` before the ℕ subtraction so reversed ranges give `0`). It also has the two MAGNITUDE-ordered signed range constructors (Malachite `exhaustive_signed_range`/`exhaustive_signed_inclusive_range`): `int8SignedRangeGen`…`int64SignedRangeGen` and `…SignedRangeInclusiveGen` enumerate the same range SET as the ascending versions but sorted by the key `(|x|, positive-first)` — realized by `List.mergeSort`ing the ascending list then `ofListNodup`, with `Nodup`/completeness transferred through `List.mergeSort_perm` (framework lemmas `nodup_range_filterMap_gen`/`mem_range_filterMap_gen`). Their counts reuse the ascending `…RangeGen_card` directly (order-independent, identical subtype). `AzRanges` adds ascending range iterators over the arbitrary-precision `AzNat`/`AzInt` (Malachite `exhaustive_natural_range`/`_inclusive_range`/`_range_to_infinity` and `integer_increasing_range`/`_inclusive_range`/`_range_to_infinity`/`decreasing_range_to_negative_infinity`) — simpler than the fixed-width ones since `ofNat`/`ofInt` round-trip unconditionally (no `MAX`/`bmod`): bounded `azNatRangeGen`/`azNatRangeInclusiveGen`/`azIntIncreasingRangeGen`/`azIntIncreasingRangeInclusiveGen` (finite, `ofBoundedBijOn`, with derived `Fintype` instances + `…_card` counts) and infinite `azNatRangeToInfinityGen`/`azIntIncreasingRangeToInfinityGen` (`[a, ∞)` ascending) plus `azIntDecreasingRangeToNegativeInfinityGen` (`(-∞, b]` descending `b, b-1, …`) — the three via `ofBijective` with `…_infinite : Infinite {…}` theorems. It also has the four MAGNITUDE-ordered `AzInt` ranges (Malachite `exhaustive_integer_range`/`_inclusive_range`/`_range_to_infinity`/`_range_to_negative_infinity`, key `(|x|, positive-first)`): bounded `azIntRangeGen`/`azIntRangeInclusiveGen` (via `List.mergeSort` of the ascending list + `ofListNodup`, counts reused from the ascending versions) and INFINITE `azIntRangeToInfinityGen` (`[a, ∞)`) / `azIntRangeToNegativeInfinityGen` (`(-∞, b]`), whose value functions dispatch on the bound's sign — monotone when the ray is one-sided, else interleave `0,+1,-1,…` up to the finite side then continue linearly — with bijectivity proved by phase/parity `split_ifs <;> omega` on the `ℤ` formula (`toInfF`/`toNegInfF`), giving `…_infinite` theorems. `LexPairs` ports the first COMPOSITIONAL generator (Malachite `lex_pairs`): given `gA : ExhaustiveGenerator A` (possibly infinite) and a FINITE `gB`, `ExhaustiveGenerator.lexPairGen`/`lexPairGenOfFinite` enumerate the newtype `LexPair A B` (a distinct `A × B` so it can carry its own generator) in lexicographic order with the LAST coordinate varying fastest — a mixed-radix odometer `k ↦ ⟨gA(k/cB), eB(k%cB)⟩`; the finite component travels as a plain computable function `Fin cB → B` plus a `Prop`-level `Function.Bijective` (NEVER the `noncomputable` `equivFin`, which would poison `#eval`), with `card = |A|*|B|`. `Basic` also has the general transport combinator `ExhaustiveGenerator.mapGen (f : S → T) (hf : Function.Bijective f) (g)` (`gen k := (g.gen k).map f`; relabel a generator along a computable bijection, `f` DATA + `hf` Prop). `LexTuples` ports `lex_triples`/`lex_quadruples` as the FLAT newtypes `LexTriple A B C`/`LexQuadruple A B C D` (faithful to Malachite's flat tuples) built by NESTING `LexPair`s and relabeling via `mapGen flattenTriple`/`flattenQuad` — reusing the pair odometer wholesale, no new mixed-radix arithmetic. The enabler is `lexPairGen_contiguous`/`lexPairGenOfFinite_contiguous` (in `LexPairs`): a composed pair generator of contiguous generators is itself contiguous (bound `cA*cB`), so the inner `LexPair …` generator can serve as the finite second argument of the next `lexPairGen` out — hence ALL BUT THE FIRST component must be finite (`B,C[,D]`), the first (`A`) may be infinite. The pair/triple/quadruple/vec generators are also genuine INSTANCES (`instExhaustiveGeneratorLexPair` etc.), gated on `[FiniteGenerator]` for the non-first components — the literal `card` is the odometer radix, keeping the instances computable — with composite `FiniteGenerator` instances (product cards) so composition nests; `instExhaustiveGeneratorLexPair_gen_eq` proves the instance path matches the `Fintype`-witness builder path (`finiteBound_none`/`finiteBound_some` from `[Fintype]+[Contiguous]` remain as the theorem-layer bridge). Counts `LexTriple.card = |A|*|B|*|C|` / `LexQuadruple.card = |A|*|B|*|C|*|D|` (via flat `equivProd`), `Infinite` when `A` is. `LexDepPairs` ports `lex_dependent_pairs` as a DEPENDENT-pair (Σ-type) generator over the newtype `LexDepPair A B` (`fst : A`, `snd : B fst`, `B : A → Type*`), where the second component's TYPE depends on the first's VALUE — for each `a` from `gA` (possibly infinite, slowest coordinate) a finite `a`-specific block of `B a` values is enumerated, then the next `a`, lexicographically. Block sizes VARY per `a` ("ragged"), so the odometer is a RAGGED prefix sum `S(i) = Σ_{j<i} card(dB aⱼ)` (via `blockSum`) rather than a fixed radix. ## Known Textbook Errors (BPR)

While formalizing *Algorithms in Real Algebraic Geometry* (Basu, Pollack, Roy), the following mathematical discrepancies were identified and corrected in Azurite:

*   **Lemma 1.10(b) (Signed Remainder Determinant Sequence):** The textbook states the identity $U_i V_{i+1} - V_i U_{i+1} = (-1)^i$. However, the textbook's definition of the cofactor sequence ($U_{i+2} = U_i - Q_{i+1} U_{i+1}$) drops the negation required to compute signed remainders ($P_{i+2} = - P_i + Q_{i+1} P_{i+1}$). When the strictly correct recurrence is used, the sequence determinant evaluates structurally to $1$ unconditionally. Azurite's formalization proves `lemma_1_10_b` equal to `1` and applies the corrected identity in subsequent proofs (e.g., Proposition 1.12).

## Building

```bash
lake build            # build the library
lake test             # build the #guard test suites (AzuriteTests)
lake build benchmark  # build the benchmark executable
```

CI (`.github/workflows/lean.yml`) builds the project, runs the tests, and
verifies that every `Azurite.*` declaration depends only on allowed axioms
via `scripts/check_axioms.lean`: exactly the standard three (`propext`,
`Classical.choice`, `Quot.sound`). `native_decide` is NOT permitted —
its last use (the Möller–Granlund reciprocal table) was replaced by a
kernel-checked pointwise `decide` — so `sorry`, `native_decide`, or any
other newly introduced axiom fails the build.

## Running Benchmarks

```bash
lake env .lake/build/bin/benchmark
```
